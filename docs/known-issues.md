# Known Issues

记录时间：2026-06-23

## 传输相关缺陷

### 客户端无法主动接收文件夹

现象：对端发送文件夹时，客户端不能像接收单文件一样主动触发接收流程。

影响：文件夹传输流程不完整，用户必须依赖当前受限路径，无法完成预期的主动接收操作。

后续排查方向：检查文件夹发送 offer、接收端 accept UI、保存路径选择、文件夹落盘或解包流程是否与单文件分支一致。

### 文件夹发送进度条异常

现象：发送文件夹时，进度条显示与实际传输状态不一致。

影响：用户无法判断文件夹当前是在准备、发送、完成还是卡住。

后续排查方向：区分文件夹打包阶段和网络发送阶段；确认进度统计使用的是临时包大小、原始文件总大小，还是已发送字节数。

### 文件夹发送完毕后发送端显示文件已被清理

现象：发送端完成文件夹发送后，界面提示文件已被清理。

影响：用户会误以为源文件夹或发送内容丢失，实际可能只是临时打包文件被清理。

后续排查方向：发送端 UI 应展示源文件夹的状态，临时包清理不应映射成用户可见的“文件已被清理”状态。

## 消息与输入体验待改进

### 消息框超链接不支持点击和独特显示效果

现状：消息文本中的链接不能点击，也没有区别于普通文本的显示样式。

目标：识别 URL，使用独立样式展示，并支持点击打开。

### 输入框和消息框文本无法框选和复制

现状：输入框、消息框中的文本无法通过鼠标选择，也无法复制。

目标：支持文本选择、复制快捷键和必要的右键菜单。

### 图片无法复制

现状：消息中的图片无法复制。

目标：支持复制图片内容，或在无法复制位图时提供明确的复制路径/打开位置能力。

### 文件和文件夹无法复制粘贴到其他聊天框

现状：聊天消息中的文件、文件夹附件无法复制后粘贴到其他联系人的聊天输入框中。

目标：支持从已有消息复制文件或文件夹附件，并粘贴到其他聊天框中重新发送；需要保留原始文件/文件夹路径校验和文件不存在时的明确提示。

## 新功能需求

### 暗色模式

目标：提供全局暗色主题，覆盖主窗口、聊天列表、消息气泡、输入框、弹窗、设置页和文件传输状态等主要界面。
验收方向：支持用户手动切换；后续可考虑跟随系统主题。

### 后台运行

目标：关闭主窗口后应用可继续在后台运行，保留网络发现、消息接收、文件传输和通知能力。
验收方向：明确区分“关闭窗口”和“退出应用”，并提供可见入口重新打开主窗口。

### 开机自启

目标：提供设置项让用户选择是否随 Windows 开机启动 RelayDesk。
验收方向：开机启动后应进入后台或正常主界面，行为需要和“后台运行”设计保持一致。

### UI 样式对齐

目标：统一现有界面里的间距、圆角、颜色、字体层级、按钮状态、列表项状态和弹窗样式。
验收方向：聊天、设置、更新提示、文件/文件夹传输、图片预览等界面遵循同一套视觉规则。
